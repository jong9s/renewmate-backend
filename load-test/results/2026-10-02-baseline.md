# RenewMate 부하 시험 기록 (2026-10-02)

## 시험 목적과 환경

- 출발 가정: DAU 5,000명 × 하루 API 요청 20회 = 하루 100,000회, 평균 약 1.16 RPS.
- 피크 계수 10배를 가정해 약 12 RPS로 추정하고 15 RPS를 피크 확인 목표로 사용했다. 이 값은 운영 트래픽의 실측값이 아니다.
- 부하 생성: Windows PC의 k6 v2.2.0. 대상: AWS EC2 `t3.micro`(2 vCPU, 1 GiB) 한 대에서 Spring Boot와 MySQL을 Docker로 실행.
- 기존 구독 조회 시험은 테스트 계정 한 명의 구독 10건을 조회했다. 5,000명에게 분산된 데이터 구조를 재현하지 않았다.
- 아래 과거 시험의 원본 k6 JSON 출력은 보관되지 않았으며, 대화에 남은 터미널 요약값을 옮겼다. 새 시험의 원본 요약 JSON은 별도 파일로 저장한다.

## EC2 측정 표본

- 100 VU 조회 시험 중 CloudWatch 5분 CPU 구간 평균 약 4.88%, 최대 약 5.44%.
- CPU 크레딧 잔액: 시험 전후 288. 크레딧 잔액이 가득 차 있었으므로 `잔액 불변 = CPU를 쓰지 않음`이라는 뜻은 아니다.
- 호스트 메모리 총량 약 911 MiB. 100 VU 시험 중 `MemAvailable` 104~105 MiB, 종료 후 106 MiB. 스왑 사용량은 시험 중 약 1,022 MiB, 종료 후 1,026 MiB.
- 메모리·스왑 값은 SSM을 통한 순간 표본이다. 지속적인 스왑 입출력이나 메모리 병목은 확인되지 않았다.

## 해석과 다음 검증

- 조회 시험은 해당 계정의 구독 조회가 목표 15 RPS에서 성공했음을 보여준다. DAU 5,000명의 서비스 전체 성능을 입증하지 않는다.
- API 업무 흐름 TPS는 DB 내부 트랜잭션 TPS와 다르다. DB TPS는 측정하지 않았다.
- 로그인과 회원가입의 동시 요청 성능은 위 시험에 포함되지 않았다. 별도 k6 시험으로 측정한다.
- 실제 데이터 규모를 반영하려면 다수 계정, 사용자별 구독·카테고리 분포, 로그인·쓰기·읽기 비율을 포함해야 한다.
